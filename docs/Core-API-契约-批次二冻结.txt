================================================================================
生成时间：2026-11-01（A-2 重跑：同步删电源类造成的成员消失，与 WorkerPipeContract 新增 6 个命令常量）
用途：批次三（Zentwik.Worker）与批次四（Zentwik.UI）引用 Zentwik.Core 时的权威清单。
      本文件之外新增或改名的 public 成员一律视为契约变更，必须同步更新本文件。

--------------------------------------------------------------------------------
【为什么重跑】
上一版用单条正则
    public (class|interface|record|enum|event|Task|void|bool|int|string|IReadOnlyList|IReadOnlyCollection)
它会漏掉四类成员：
    1. 接口成员 —— 接口成员没有 public 修饰符（ILogService 的成员一个都没进）
    2. public static / public const / public readonly 字段
    3. public async Task 方法
    4. public sealed class / public partial class / public static class
本版改为「先扫所有以 public 开头的行，再用状态机补扫 public interface 块内的成员」，
不做类型白名单。

--------------------------------------------------------------------------------
【三段的扫描命令（逐字可复现）】
段 1 —— 所有以 public 开头的成员（不论修饰符组合）：
  grep -rnE "^[[:space:]]*public[[:space:]]" \
      Zentwik.Core/Services/ Zentwik.Core/Ipc/ Zentwik.Core/DependencyInjection/ \
      Zentwik.Core/Helpers/ \
      --include=*.cs | grep -v "/obj/" | grep -v "/bin/"

段 2 —— 接口成员（接口成员无 public 修饰符），awk 状态机：
  对每个含 "public interface" 的文件逐行扫描（范围同段 1，含 Helpers/）；
  遇到 4 空格缩进的 "}" 退出接口块；跳过注释行、空行与孤立 "{"，其余行即接口成员。

段 3 —— 附录：Serialization/IpcJsonContext.cs
  该文件在 Serialization/ 下，不在段 1/2 的目录范围内，但它是 IPC 序列化契约本身，
  批次三 Worker 必须复用同一个上下文，因此单独列出（范围收窄不能变成缺项）。

# 批次五追加（2026-11-02）：AutoStartService 启动参数常量更名

删除：AutoStartService.cs:55   public const string SilentArgument = "-silent";
新增：AutoStartService.cs:69   public const string OpenUiArgument = "--open-ui";

（行号说明：原 SilentArgument 在 :55，删除后 OpenUiArgument 在 :69。
  偏移 14 行的来源：旧常量的注释是 1 行（原 :54 的 <summary> 单行），新常量的注释是 15 行
  （:54–:68），注释净增 14 行，代码本身没有位移。）

【为什么删】
  双进程架构下，登录自启的任务只负责拉起 Worker（常驻 + 写 SMU）；「要不要显示界面」
  由 Worker 启动后按配置决定，不再是启动参数能表达的语义。Worker 的 Program.Main
  只把 args 交给 Host.CreateApplicationBuilder，没有任何地方读 -silent —— 死代码。

【实测：-silent 不会崩】
  批次五实测 `Zentwik.Worker.exe -silent`：进程存活 5 秒以上、管道 ping 返回
  {"Version":1,"Success":true,"Message":"pong"}、startup_crash.log 未增长（18293 字节不变）。
  即 CommandLineConfigurationProvider 容忍裸开关。因此删除理由是「语义无效」，
  不是「会崩」——原任务书假设的 FormatException 未复现。

【兼容性】
  该常量无其它引用（全仓 grep 仅 AutoStartService.cs 内部 3 处，已一并改掉）。
  移除 public const 属于契约变更，按本文件头部约定在此登记。
